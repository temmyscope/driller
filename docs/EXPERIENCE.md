# driller — Experience Spine

> Lean UX pass feeding architecture, not a standalone gate. Single-persona developer tool (Supervising Engineer). Register: see `DESIGN.md` § Brand & Style — terminal-native, resolved 2026-09-23. This spine's behavioral content never depended on that resolution and is unchanged by it.

## Foundation

Single-surface Electron desktop app — no responsive/multi-platform concern in v1 (PRD §2.2, §6.2).

## Voice and Tone

Microcopy speaks in the engineer's own vocabulary — real identifiers, real module paths, no anthropomorphized tool-voice. Brand register lives in `DESIGN.md`; this table is behavioral wording only.

| Do | Don't |
|---|---|
| "PaymentService.charge — Blast Radius: 4 Nodes" | "This function affects a few other things!" |
| "Summary may be stale — source changed since generation" | "Oops, this summary might be out of date!" |
| `[UPDATED 2026-10-21]` "No path found in indexed code for that query." — and "— this section only." when a section is selected, since the search was bounded to it. Never a bare "No path found", which reads as proof of absence | "Hmm, we couldn't find anything 🤷" / "No path found" |
| "Coverage incomplete for this file — read source directly" | "We're not 100% sure about this one" |
| `[ADDED 2026-09-30, P4-4]` "12 edges cross into `web/` — not shown in this section" | "Some connections are hidden" |
| `[ADDED 2026-09-30, P4-4]` "3 changed Nodes in `api/` — Switch to `api`" | "Heads up — this PR changed other stuff too!" |
| `[ADDED 2026-10-03, P4-4h — founder decision; wording per review round 1, 2026-10-04]` Cross-section edges are split by direction, a 0 direction left out, each count with its own noun: "1 edge into `web/`, 3 edges from `web/` — not shown in this section" (several sections joined with " · ": "… · 3 edges into `docs/` — …"). This supersedes the "12 edges cross into `web/`" wording above. "Changed elsewhere" leads with the section and also names changed contracts and top-level-only files, for sections in the same git repository only: "`api/`: 1 changed Node · 1 contract changed · top-level code changed in 1 file — Switch to `api`" (read with the change count as "Also changed in `api/`: …"); this supersedes the "3 changed Nodes in `api/`" order above | "Some connections are hidden" / "This PR touched other stuff too" |

## Component Patterns

| Component | Behavior |
|---|---|
| **Node** | The atomic map unit. Always shows: identifier (function/method/module name, verbatim from source), one-line AI summary, and a compact signal strip. Selecting a Node opens Node detail without leaving map context (FR-4). |
| **Signal strip** | The compact row of Risk Overlay indicators on a Node. Three visually distinct signal families render side by side, never merged into one ambiguous icon: **deterministic** (complexity, Blast Radius, coverage gap, hotspot, and `[ADDED 2026-10-21]` co-change — FR-7; its glyph `⇄` reads as the two-way movement it describes and shares no stroke with the other five), **LLM-judgment** (qualitative risk — FR-8), **ingested finding** (external PR-bot result, shows origin tool — FR-9). Each family independently toggleable (FR-7, FR-8); ingested findings are absent entirely when no PR-bot is configured, not shown empty. |
| **Changes with** | `[ADDED 2026-10-21]` Node detail's section naming the files this Node's file has a history of changing alongside, each with the commits behind it and how often the two moved together — never a percentage driller did not compute. Paths only, in monospace, with no link: a file is not a map Node, so there is nothing to navigate to and none is offered. Always closes with the honest-copy line, because the whole risk of this section is being read as a dependency: "From git history: these files have changed in the same commits. It does not mean one uses the other." Absent entirely when nothing qualifies — a project with no git history shows no section rather than an empty one or a zero. |
| **Staleness Indicator** | A distinct, always-visible treatment on a Node's summary when stale (FR-16), never the same visual weight as a risk signal — staleness is about the summary's trustworthiness, not the code's risk, and conflating the two would undercut the "don't present summaries as settled fact" trust story (PRD §4.9). |
| **Mode switcher** | A persistent, always-visible control (not buried in a menu) for Code Map / PR Review Mode / Health Audit Mode — mode is a first-class state, not a settings toggle. |
| **Section bar** | `[ADDED 2026-09-30, P4-4]` A tmux-style tab row under the header, visually quieter than the Mode switcher (DESIGN.md `section-tab`), shown only when the indexing-scope allowlist has 2 or more entries — never a bar with fewer. Tabs, in order: `all` first (exactly today's whole-scope view), then one tab per allowlist entry in allowlist order, each labelled with the verbatim allowlist path and its Node count (`api 412`); no per-section renaming in v1. **Nearest entry wins:** with nested entries (`apps`, `apps/web`), a file belongs to the longest entry that contains it, so each file is in exactly one section, and nothing is rejected at save. Selecting a section recomputes every surface for it, and every number comes from running the scope filter with that section's own scope — never from subtracting it out of `all`. The mode is kept. **Cross-section data is counted, never silently dropped:** a footer line states the edges that cross into other sections ("12 edges cross into `web/` — not shown in this section"); Node detail's "Calls into other sections" lists each callee with its section and the action "Switch to `web`"; PR Review states changes outside the section ("3 changed Nodes in `api/` — Switch to `api`"). Each line is absent when its count is 0, and none appears in `all`. **Remembered:** the last section is saved per project (Architecture AD-5); a saved path no longer in the allowlist falls back to `all` silently — no notice, no empty map. A section is never a project, repo or workspace — see § Inspiration & Anti-patterns, "cross-repo switcher". |
| **Path Trace result** | Renders two ways simultaneously: as a highlighted route directly on the Code Map (never a text-only list — FR-10), and as an ordered step list an engineer can step through linearly when the graph view alone is too dense to follow. `[ADDED 2026-09-23]` The step list's resolved visual is an indented call-stack view (hop circle, tree-indent glyph, identifier, module) — never a duration/timing figure per Node, since Path Trace resolves statically and driller never executes code (see DESIGN.md § Do's and Don'ts). |
| **Coverage Gap** | A Node lacking full graph coverage (FR-2) shows this instead of a confident-looking summary; visually distinct from the Staleness Indicator (different failure mode — missing data vs. outdated data). |
| **PR Review metrics table** | `[ADDED 2026-09-23]` In PR Review Mode, pairs the Code Map canvas (kept purely structural/spatial) with a sortable table listing every changed/affected Node's complexity, Coverage Gap, Blast Radius, and ingested findings side by side, complexity and Blast Radius each paired with an inline bar (`[UPDATED 2026-09-30, P4-3d]` Decision 3: bars on those two columns only; every column really sorts). Lets an engineer scan and compare many Nodes' signals at once rather than reading one Node's badge strip at a time — the canvas stays the map, the table is the audit surface. A changed Node's row is visually ruled to match its canvas card. Additive, not a replacement: the canvas's own Signal strip badges are unchanged. `[ADDED 2026-10-15, P5-i — founder decision 1.1]` **Sort rules.** By default rows are in the review order: changed Nodes first, then hop ascending, then blast radius descending, then id. Activating a header sorts by that column; activating it again flips the direction (there is no third "default" state: a new diff scope, a refresh or a project switch restores the default order). A first click starts descending on complexity, blast radius and findings, and ascending on node (case-insensitive name, then file) and hop (`changed` before 1, 2, …). Findings sort by count, then severity. On those columns a `—` (no value) sorts last in both directions. Ties break on Node id ascending in both directions. Each sort is announced ("Sorted by blast radius, descending."). Contract rows stay pinned above the sorted Node rows, and with no Node rows the headers are inert (P5-g). **The tests column is the exception, on purpose:** it orders `gap` < `—` < `covered`, and a first click sorts *ascending*, so the first view leads with the untested changed code, which is the reason to sort this column. Here `—` is a value ("no LCOV data for this file" or "no function-level proof"), not a missing one, so it sits between the two and flips with the direction. Descending therefore reads `covered`, `—`, `gap`. This deliberately departs from P4-3d's "numeric columns start descending" and "`—` last in both directions" (P4-3f; founder-approved 2026-10-15). |
| **Health Audit cluster card** | `[ADDED 2026-09-23]` `[UPDATED 2026-09-24]` Health Audit Mode's resolved composition (FR-13): Nodes are grouped into cards by the containing directory, each card carrying one heat label and listing its own specific Nodes with their driving signals. Heat is derived from **risk-signal count, never severity** — the count of a Node's deterministic signals plus its LLM judgment, banded exactly as the Code Map's existing cluster tint bands it — and a card takes the band of the *highest count on any single Node it contains*, never the sum, so one bad Node makes a module hot rather than a large directory doing so by volume. Every heat label states that count alongside the band ("hot · 7 signals"), never a bare adjective. A Node's row shows its real signal values (e.g. "complexity 21", "radius 14") or "healthy" when it carries none — never a percentage or a severity rank: no risk-signal contract carries a severity field, and `test-coverage-gap` is a boolean flag, so a "74% gap" figure would be fabricated (the earlier wording of this row asserted both, and driller could produce neither). Realizes the IA's "risk signals clustered/heatmapped" description concretely — clustering is by structural directory grouping and signal volume, not spatial graph position the way PR Review Mode's canvas is. `[UPDATED 2026-09-24]` **A Node's row is a control, not a read-out: activating it opens Node detail for that Node** — the same panel, the same one-action open, and the same close behavior as selecting a Node on the Code Map canvas, never a second detail surface. Mode does not change: the panel opens over the grid, and closing it returns the engineer to the grid where they left it. This is how FR-17 holds on this surface — the row shows Risk Overlay signals, and Node detail is where each one's exact source range is one action away — so the row never needs a second, nested target of its own. The capped "+N more Nodes"/"+N more modules" lines are deliberately NOT activatable: they are counts of what the display caps dropped, not Nodes, so there is nothing for them to open and they must not look as if there were. |
| **Sync status** | `[ADDED 2026-09-23]` `[UPDATED 2026-09-24]` A persistent, minor footer line stating recency in plain relative time — "Last synced N ago" (PR Review Mode, reflects the diff/blast-radius computation). Informational only, never an Actionable Notice — there's nothing wrong to report. **The Health Audit Mode variant ("Last full scan N ago") is withdrawn, not deferred:** driller records no scan timestamp anywhere — not on the index, not on a Node, not in settings — so the figure could only be fabricated, and this spine does not specify data the product cannot produce (the same correction the "74% gap" row above already took). Health Audit Mode therefore ships with no footer at all. Re-specify this only alongside a real timestamp source; a designer should not read the shipped surface as having dropped a line it was supposed to have. |
| **Canvas edges** | `[ADDED 2026-09-23]` PR Review Mode's edges leading out of a changed Node render in a distinct, `{colors.accent}`-matching treatment from every other edge on the canvas — the same "changed" meaning `accent` already carries elsewhere (Node border, prefix) extended onto the graph's own connective lines, so the directional flow away from a change is visible on the edge itself, not only inferable from which two Nodes it touches. |
| **Backend config control** | In Settings: a choice between local/on-device model and bring-your-own-key cloud provider, with a key-entry field when a cloud provider is selected (FR-6). Switching regenerates summaries only — the graph index is untouched. |
| **External editor control** | `[ADDED 2026-09-06]` In Settings: a required choice among VS Code / JetBrains / System default (Story 1.10, Architecture AD-23), defaulting to System default. Only the named-editor options deep-link to the exact line via that editor's own URI scheme; System default opens the file through the OS's generic file association and cannot jump to a line — the control's copy states this plainly, never implying parity. |
| **Actionable Notice** | The shared shape for every "something needs attention" state driller shows — distinct from a Node-level trust signal (Staleness Indicator, Coverage Gap) and from a purely informational state (Empty, Indexing). Three fixed parts, no exceptions: an indicator distinguished by shape/icon, never color alone (Accessibility Floor); one specific sentence naming what's true, in the Voice and Tone table's register (never vague, never an apology); and, when one exists, exactly one clear next action — never a paragraph of options. Instances: see § State Patterns below — each has its own triggering condition. Each instance supplies only its own icon and sentence — never a bespoke layout. |

## State Patterns

| Surface | State | Behavior |
|---|---|---|
| Code Map | Full map layout | `[ADDED 2026-10-20]` Full lays its cards out by the **call graph**, not the order the Nodes arrived in: `communities.ts` partitions the Nodes into communities by who calls whom, and each community is drawn as its own block of columns by hop depth (the same layered placement the Revealed view uses). So a caller and its callees sit together, and the edges between them are actually drawn — the canvas only draws an edge when both its ends are un-clustered cards, which over the previous index-ordered grid meant the call structure was mostly invisible. `[UPDATED 2026-10-21]` **A community is named after the file holding most of its members, or else after the member its own community calls most** — a real module path or a real identifier, never an invented name and never a folder (§ Voice and Tone). The file wins only when it holds at least half of them, which is what keeps the name honest across languages: on driller's own repository the biggest file in a community holds a median 72% of its members, so most communities read as `apps/desktop/renderer/src/CodeMap.tsx` rather than `onClick`; on a Go API the median is 27%, as low as 6%, where naming a 35-member community after a file holding 2 of them would simply be false, so the identifier stands. The hub is counted by calls **from inside the community**, not across the whole map, or a map-wide accessor wins over the group's own centre (`current` over `decrypt`). Where two communities would still read alike — Go's `New` named three of four in one service — each gets its hub's own file added, so no two cards on a map are indistinguishable. Two kinds of card get a plain grid instead of a structural position, because they have no call structure to show and a layout must not imply one they have not earned: the Nodes in the "unreferenced in indexed code" group (no call edge at all — the same honest qualifier the candidate copy uses), and the render-only folded Type/Module cards. `[ADDED 2026-10-21]` **A group too small to be a module gets no card of its own.** A community still under four members after merging had no neighbour to merge into — that is exactly why it survived — so every such island is pooled into one community that states how many it holds ("14 isolated groups"), sitting after every real module and before the unreferenced group. On driller's own repository this is the difference between 42 cards and 27: the fourteen largest communities hold about 98% of the connected Nodes, while the tail held twenty-two Nodes across twenty-seven groups, fourteen of them bare pairs. A lone island is left as itself — pooling one group into a bag of groups would say less than the group does. The pooled group's calls are all internal by construction, so its cohesion reads as every call inside; that is arithmetically true and says nothing about quality, which is why its name leads with what it actually is. **Below 40 connected Nodes the map is not partitioned at all** — it is one block of columns. Grouping only earns its place when a map is too big to take in at once, and on a small map splitting would put a caller in a different block from the callees it calls. This is layout only: no risk signal, Blast Radius count, Path Trace result, PR Review changed set or Health Audit card changes because of it. |
| Code Map | Grouped (Full map's default) | `[ADDED 2026-10-20]` Full opens on the **community cards**, not on every Node: one card per community from § State Patterns, "Full map layout". A card states what the call graph grouped — the word `community`, its name in monospace (§ State Patterns, "Full map layout": the file most of its members share, else its own hub's identifier), its Node count, and its **cohesion as the two real counts it comes from** ("12 of 15 calls inside", never a derived percentage: the same discipline that kept a fabricated "74% gap" off the Health Audit row) — plus "↗ N out" when it calls outside, absent when it does not, so the traffic is never a silent 0. The call traffic between two cards is drawn as an edge carrying its **count as visible text** ("4 calls"), never width or colour alone. A card is not an LOD cluster and not a Health Audit cluster (Architecture §8 names all three): it is told apart by shape — a square-cornered panel with a leading rule, against the cluster's dashed pill — never by colour, and it is never swept into an LOD cluster that would relabel it "Cluster of N Nodes". **A persistent "Grouped / All Nodes" toggle** sits beside the "Revealed / Full map" one: `All Nodes` draws every Node, which is what Full drew before this view existed and the way back to the whole map at once. Switching there is which view you are in, not a step within one, so it is not a Back step — expanding or collapsing one community is. **One known limit, stated rather than hidden:** a link edge is drawn only between two collapsed cards; with one end open there is no single card on that side to anchor it to, and picking one of its members would invent structure the graph does not have, so the card's own "↗ N out" carries it instead. |
| Code Map | Nothing to group | `[ADDED 2026-10-20]` Actionable Notice, in Full map, beside the Panel's status line — never a silent absence of cards. Three cases, each a real outcome of a real partition rather than a failure, so each states what is true in one sentence and offers no action: **one community** ("One community in indexed code (`charge`, 23 Nodes) — nothing to group, so every Node is shown."), **no call edges at all** ("No call edges in indexed code — all 7 Nodes are unreferenced, so there is nothing to group."), and **too few Nodes** ("12 Nodes in indexed code — too few to group, so every Node is shown." — below 40, the same floor the partition uses: grouping only earns its place when there is enough to hide, and on the seven-Node `path-trace-basic` fixture it would hide all seven behind two cards). In all three the Nodes themselves are drawn, and the "Grouped / All Nodes" toggle is absent rather than offering a choice that would do nothing. |
| Code Map | Indexing (progressive, not blocking) | Structural indexing and AI summary generation complete on different timelines. The map is explorable (structure, navigation, Risk Overlay for already-processed Nodes) as soon as structural indexing finishes; individual Nodes show a lightweight "summary pending" state rather than blocking the whole map. Never a blank screen (FR-1). |
| Code Map | Revealed | `[ADDED 2026-09-30, P4-7]` Opt-in view; Full map stays the default (whether Revealed becomes the default is decided after dogfooding). Only candidate entry points and the Nodes drilled into from them are drawn, in a layered layout (column = hop depth). Each candidate states its reason: "no callers in indexed code · reaches N Nodes", or "pinned by you". `[UPDATED 2026-10-15, P5-e]` Files whose name contains 'harness' or 'fixture' are never suggested (pin one to list it). It is always called a "candidate", never presented as the program's one true start, and every reach count and "no callers" claim comes from real fetched edges, qualified "in indexed code" (Architecture AD-13 (f)). A persistent "Revealed / Full map" toggle switches views; switching to Full and back keeps the reveal state. **Per section** (founder decision 2026-10-04): with a section selected in the Section bar, candidates, their reach and every drill step are computed within that section alone, like every other surface; `all` is the whole scope. A section switch restarts the reveal from the new section's candidates. |
| Code Map | No entry candidates | `[ADDED 2026-09-30, P4-7]` Actionable Notice, in Revealed only. No Node qualifies as a candidate (e.g. fully cyclic code, where every Node has a caller in indexed code) — states that and offers one action, "Show full map", which switches to Full. Never an empty canvas. A failed candidate listing (AD-13 (f)'s `error` state) uses the same notice with its own sentence and the same action. |
| Node detail | Coverage Gap | See Component Patterns. Applies per-Node, not as a global banner, so it doesn't obscure the rest of an otherwise-usable map. |
| Node detail | Staleness Indicator active | See Component Patterns. |
| PR Review Mode | Changed Node | Nodes touched by the scoped git diff are visually distinguished from unchanged Nodes (FR-11) — a distinct rendering, not just a badge, since it's the organizing fact of the whole mode. |
| PR Review Mode | No changes to review / not a git repository | Actionable Notice. The selected base ref produces an empty diff, or the opened folder isn't a git repository (FR-1 detects and confirms this before indexing) — states explicitly rather than showing an empty map with no explanation. |
| PR Review Mode | No base ref resolvable | Actionable Notice. Base ref was omitted and no upstream-tracking or configured default branch could resolve one — distinct from the two states above, never silently guessed (Architecture AD-13). |
| Path Trace | No path found | Actionable Notice. States that explicitly (FR-10) rather than returning an empty or ambiguous result; distinct from a loading/searching state. |
| Path Trace | Ambiguous multiple matches | Actionable Notice. A query matches more than one plausible entry point — presents the candidates for disambiguation rather than silently picking one or merging results. |
| Backend config | Cloud selected, no key entered | Actionable Notice. Summary generation for that backend is blocked with a clear reason, not a silent failure. |
| Backend config | No summary backend available | Actionable Notice. Local inference failed (download/checksum) and no cloud key is configured — distinct from a Coverage Gap or a pending summary; points directly to configuring either option. |
| PR-bot ingestion | Tool not found | Actionable Notice. The opted-in PR-bot's CLI isn't installed on this machine — distinct from the tool running and finding zero issues; points to installing it. |
| External editor | Editor not found / handler unavailable | `[ADDED 2026-09-06]` Actionable Notice. The OS can't resolve the configured editor's URI scheme (or, for System default, no file association exists) — distinct from the editor simply not being the user's preference; points to checking the editor is installed or changing the Settings preference. |
| Any (Graph Service) | Backend degraded | Actionable Notice. When the Graph Service's backend is unavailable (PRD §7 Reliability), shows an explicit degraded-state message; never silently serves stale or wrong structural data as if current. |
| App | Empty (no project open) | Recent projects surface, or a clear "open a folder" affordance; never a blank canvas with no next action. Informational, not an Actionable Notice — there's nothing wrong here. |
| Health Audit Mode | Clean repo (no hot/warm clusters) | `[ADDED 2026-09-23]` Renders the same cluster-card layout with every cluster carrying `healthy` heat dots — no special-case empty state or congratulatory copy. Deliberately not an Actionable Notice or a distinct empty state: a clean repo is a normal, unremarkable outcome of the same scan, not an absence of data to explain. |
| Any focusable element (Node, mode-switcher tab, metrics-table row, form control) | Keyboard focus | `[ADDED 2026-09-23]` See DESIGN.md § Components, `focus-ring` — a visible outline, layered on top of (never replacing) whatever other state treatment the element already carries. ## Interaction Primitives

- **Traverse by edge** — clicking an edge or a "called by / calls" affordance re-centers the map on the connected Node, with back/forward history (FR-4).
- **Drill from entry point** — `[ADDED 2026-09-30, P4-7]` in the Code Map's Revealed view (§ State Patterns, "Revealed"), expanding a Node reveals its callees in indexed code (a call or a usage both count, the same edges a candidate's reach counts). Two layers open when the next layer is 12 Nodes or fewer; otherwise one. A layer of more than 30 Nodes shows the top 30 by reach plus an activatable "+N more callees" stub. `[CLARIFIED 2026-10-04, P4-7e review]` The 30 cap counts each parent's own newly revealed callees, not a whole layer: in a two-layer step, each Node in the first layer shows up to 30 of its callees, with its own stub. Collapse hides that Node's revealed subtree; candidates always stay. A Node already shown renders as a "↺ shown above" reference, never as a duplicate card. Each expand, collapse or stub step is a step in the same renderer-local back/forward history as Traverse by edge, so Back undoes it. The engineer can pin or unpin any Node as an entry point from Node detail; pins persist per project (Architecture AD-5, "Entry pins") and rank ahead of heuristic candidates, each stating "pinned by you". The 12 and 30 thresholds are named constants (FR-3, FR-4, UJ-2).
- **Open a community** — `[ADDED 2026-10-20]` on Full map's Grouped view (§ State Patterns), activating a community card — or `+` on the focused card — draws that community's own Nodes in place of it; `−` on any of those Nodes closes it again, since while a community is open it has no card of its own to press. Enter on a Node keeps opening Node detail. Neither key acts with Ctrl, Cmd or Alt held, so app and browser zoom are untouched. Each open and each close is **one step** in the same renderer-local back/forward history as Traverse by edge, so Back undoes exactly one of them; the "Grouped / All Nodes" toggle is not a step. Every open, close and Back/Forward is announced through the same one `role="status"` region the Revealed view speaks through, naming the community and what changed ("Expanded `charge` — 23 Nodes", "Collapsed `charge` — 23 Nodes hidden", "Back: Collapsed `charge` — 23 Nodes hidden").
- **Toggle overlay layers independently** — deterministic and LLM-judgment signal layers each toggle on/off without affecting the other (FR-7, FR-8).
- **Expand Blast Radius depth** — interactive 1-hop/2-hop/... expansion from a changed Node in PR Review Mode (FR-12).
- **Search-to-trace** — free-text or structured entry-point query returns a Path Trace (FR-10); search is always reachable, not mode-gated.
- **One click to source** — every summary and every risk signal opens its exact source range in one action, always (FR-17) — this is the trust mechanism, so it has zero friction by design, not a "view source" button buried in a menu.
- **Open in external editor** — `[ADDED 2026-09-06]` from the in-app source view, the Settings-configured editor launches at the exact file/line (Story 1.10); only a named editor can jump to the line, System default cannot, and the affordance never lets the exact range go silently unspecified.
- **Regenerate on demand** — explicit user-triggered action from the Node detail view to refresh a summary flagged by the Staleness Indicator (FR-16).
- **Switch summary backend** — from Settings, choosing local model or entering a cloud provider key (FR-6) takes effect on next summary regeneration, no index rebuild.

## Accessibility Floor

PRD §7 leaves formal conformance unset for v1 (`[ASSUMPTION]`, PRD Open Question 1) — but two behavioral floors are load-bearing regardless of that decision, because they're inherent to how Risk Overlay signals communicate meaning:

- **Never color-only.** The three signal families (deterministic / LLM-judgment / ingested finding) and the Staleness Indicator / Coverage Gaps must be distinguishable by shape or icon, not color alone — color-blind engineers are squarely inside driller's own target persona (senior engineers), not an edge case to deprioritize.
- **Keyboard-navigable map traversal.** Edge-following (FR-4) and mode switching must have a keyboard path, not only pointer/click — consistent with the tool's own "respect how engineers work" positioning (many live in the keyboard). `[ADDED 2026-09-23]` Realized visually by DESIGN.md's `focus-ring` component (see § State Patterns, "Keyboard focus" row). `[ADDED 2026-09-30, P4-4]` The Section bar is a `role="tablist"` (`aria-label="Section"`) of `role="tab"` buttons: Arrow keys move focus (wrapping), Home/End jump to the first/last tab, and Enter/Space activate — manual activation, because each activation refetches the map. The active tab carries `aria-selected` plus an underline, never colour alone. Each section change is announced through one `role="status"` region ("Showing section `api` — 412 Nodes" / "Showing all sections — 1,204 Nodes"). `[ADDED 2026-10-20]` On Full map's Grouped view a community card is a `role="button"` with `aria-expanded="false"` and an accessible name that spells the whole card out, including the action ("Community `charge`, 23 Nodes, 12 of 15 calls inside, 3 calls out, expand"); its "↗ N out" glyph is `aria-hidden`, and each link edge carries an `ariaLabel` saying its count in full, qualified "in indexed code". Its keyboard path is § Interaction Primitives, "Open a community", and every step is announced through the one status region. `[ADDED 2026-09-30, P4-7]` In the Code Map's Revealed view, `+` and `−` expand and collapse the focused Node (never with a modifier key held, so zoom shortcuts are untouched); Enter keeps opening Node detail. Every reveal, collapse and Back/Forward restore is announced through one `role="status"` region, naming what changed ("Revealed 3 callees of `handleRequest` in 2 layers"). The candidate, pinned and stub states each carry a glyph plus text — "◎ candidate", "⚑ pinned by you", "+N more callees" — never colour alone.
- **Contrast.** `[ADDED 2026-09-23]` Every badge fill/ink pair (DESIGN.md § Components) meets WCAG AA's 4.5:1 normal-text minimum — verified per pair, not assumed; see DESIGN.md's own Signal strip / badges bullet for the computed ratios.

Full WCAG-level conformance target remains an open architecture/product decision (PRD Open Question 1).

## Key Flows

Mirrors PRD §2.3 UJ IDs verbatim.

- **UJ-1. Dani approves an agent's change without reading the raw diff.** (PRD §2.3)
  - **Persona + context:** Dani, a senior engineer directing three parallel coding agents on a mid-size service, gets a "task complete" notification from one of them.
  1. Dani switches to PR Review Mode and selects `main` as the base ref.
  2. driller computes the local git diff and highlights the changed Nodes on the Code Map, expanding their Blast Radius.
  3. One changed Node, `PaymentService.charge`, shows a Risk Overlay badge — an ingested finding from Dani's configured PR-bot.
  4. Dani opens that Node's detail and reads its AI summary (not stale — generated after this change) alongside the ingested finding.
  5. Dani runs a Path Trace from the changed function toward the payment-write Node three hops away.
  - **Climax:** `[CORRECTED 2026-10-21]` The Path Trace finds no route from the change to the flagged payment boundary **in indexed code**, and Dani has structural evidence rather than a guess — evidence about what driller indexed, which is not the same as proof that no such route exists. The index is best-effort (the backend's own language coverage has gaps, a file may be `parse_partial`, and a selected section bounds the search further), so the earlier wording of this climax — "comes back clean" — promised something driller cannot produce. Dani weighs it with the Coverage Gap flags, not instead of them.
  - **Resolution:** Dani approves and merges, in a fraction of the time a full diff read would have taken.
  - **Failure:** If graph coverage is incomplete for a touched file, that Node shows the Coverage Gap state instead of a confident-looking summary (§ State Patterns) — Dani reads that one file directly instead of trusting an absent summary.

- **UJ-2. Sam audits an inherited AI-heavy codebase before a client handoff.** (PRD §2.3)
  - **Persona + context:** Sam, a tech lead, inherits a codebase that's had six months of heavy AI-agent contribution and needs a structural read before signing off on a handoff.
  1. Sam opens the repo folder in driller for the first time; no prior index exists.
  2. driller begins indexing, showing progress — already-indexed Nodes are explorable immediately (Indexing state, § State Patterns).
  3. Sam lands in Health Audit Mode by default and sees hotspots and low-coverage Nodes clustered around one module.
  4. Sam runs a Path Trace from a GraphQL mutation entry point through that module to its database write.
  - **Climax:** The trace confirms the suspected risk is real and structurally significant, not a false positive.
  - **Resolution:** Sam produces a punch list grounded in the actual call graph, not a guess from skimming file names.
  - **Failure:** If the repo is too large to fully index synchronously, driller shows a progressively-completing map (Indexing state) rather than blocking Sam from starting on the portion already indexed.

## Inspiration & Anti-patterns

Behavioral half only — visual-direction inspiration/rejection lives in `DESIGN.md` § Brand & Style. Triggered by `.memlog.md`'s rejected-direction record and by PRD §5 Non-Goals / the brief's competitive positioning.

- **Anti-pattern — inline-comment review bots.** CodeRabbit/Qodo-style tools present findings as a wall of inline PR comments. driller does not replicate that interaction: ingested findings (FR-9) are one signal family within the Node's signal strip, never the primary or only interaction surface.
- **Anti-pattern — IDE creep.** driller is not an IDE (PRD §5): no code editing or execution surface, ever, regardless of how convenient a "quick fix" affordance might look later.
- **Anti-pattern — external-editor hand-off growing into in-app editing.** `[ADDED 2026-09-06]` The "open in external editor" affordance (Story 1.10) is a one-way hand-off — it must never grow a text-input, save action, or any edit affordance inside driller itself; that would be the IDE-creep anti-pattern above, arrived at by a different door.
- **Anti-pattern — auto-approve/auto-merge.** No action anywhere in the UI approves or merges on driller's own authority (PRD §5) — every decision surface informs Dani/Sam; none decides for them.
- **Anti-pattern — BI dashboard.** No stat-tile landing screen, no vanity-metrics summary view as an entry point — see DESIGN.md § Do's and Don'ts for the visual half of this rule.
- **Anti-pattern — cross-repo switcher.** No multi-repo picker or cross-repo view in v1 (PRD §5, §6.2) — Recent projects is single-repo-at-a-time, full stop. `[ADDED 2026-09-30, P4-4]` **The Section bar is not a cross-repo switcher.** A section divides the one opened folder by that folder's own indexing-scope allowlist; it never opens, indexes or merges a second folder, and it adds no project picker. `all` is exactly the opened folder's whole-scope view, and copy never calls a section a project, repo or workspace.
- **Inspiration, partially adopted — DeepWiki's source-linking.** DeepWiki's "every AI claim links to its source" discipline is worth keeping (driller's own FR-17 does this); its chat-Q&A interaction model is not adopted — driller stays map-traversal-first, not conversation-first.
